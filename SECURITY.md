# Security and private data

AgentJournal is independent community software. Local transcripts, saved notes and excerpts may contain sensitive information. Model generation uses the selected CLI's configured provider after consent; rendering/share previews remain local.

Never attach real conversations, journals, indexes, auth files, API keys, certificates, account/usage output or personal screenshots to public issues. Use `--demo` and synthetic examples. Version numbers and a minimal redacted reproduction are usually enough.

For a potential vulnerability, use GitHub private vulnerability reporting if the repository has it enabled. Otherwise request a private reporting channel from the maintainer with a non-sensitive overview; do not publish exploit details or credentials while arranging contact. If a credential is exposed, revoke it promptly—removing a file from the latest commit does not remove old copies.

The privacy guard is a heuristic, not a full security audit. Signing/notarization establishes additional distribution checks, not a guarantee that all code or generated advice is safe. The app does not execute transcript instructions or advisor next steps.
